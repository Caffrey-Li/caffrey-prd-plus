# 导入说明（写给负责导入飞书的 agent）

这是 caffrey-prd-plus 生成的需求文档全包。请把它导入飞书知识库（Wiki），保持页面层级和文档结构，**不要改写内容**。

## 包里有什么

| 文件 | 内容 |
| --- | --- |
| `manifest.yaml` | Wiki 页面清单（标题、文件、层级）和图片清单 |
| `pages/` | 每个 Wiki 页面一个 Markdown 文件；`pages/01-xxx/` 子目录中的文件是 01-xxx 的子页面 |
| `images/` | 线框图 PNG（同名 SVG 是源文件，不用导入） |

## 导入步骤

1. **确认位置**：问用户导入到哪个知识空间、哪个父节点下。用户没说时不要自行选择。
2. **建节点**：按 `manifest.yaml` 中 `wiki` 的顺序和层级（level）逐个创建文档节点，节点标题用 `title`。
3. **转换正文**：把 Markdown 转成飞书文档块：

| Markdown | 飞书文档 |
| --- | --- |
| 第一个 `# 标题` | 已作为节点标题，正文中不再重复 |
| `##`、`###`、`####` | 标题 2、3、4 |
| 表格 | 表格，第一行作为表头 |
| ` ```text ` 代码块（文本线框图、用户路径图） | 代码块，语言选纯文本，保持换行和空格 |
| `> 引用` | 引用块 |
| 列表、加粗 | 对应的列表、加粗 |
| `![说明](../images/xxx.png)` | 上传 `images/xxx.png`，在原位置插入图片；“说明”作为图片描述 |

4. **保留标记**：`【TBD：……】`、`【待确认】`、`◀ 新增` 等标记原样保留，可以加黄色背景方便查找，但不要删除或改写。
5. **核对**：每个页面导入后，核对标题数量、表格数量、图片数量与 Markdown 一致。
6. **汇报**：告诉用户每个节点的链接，以及有没有导入失败的内容。

## 没有 agent 时手动导入

1. 在飞书云文档中选择“导入” → Markdown，逐个导入 `pages/` 下的文件，并按 `manifest.yaml` 的层级移动到 Wiki 中。
2. 图片不会随 Markdown 自动导入：打开 `images/` 文件夹，把图片拖到文档中对应的图片占位处。
