# 示例：检查一份已有 PRD

用户发来一份其他人写的 PRD，说“帮我检查一下这个 PRD”。下面是被检查的原文和 caffrey-prd-plus 输出的检查报告。

## 被检查的 PRD

```text
会员积分兑换 PRD v1.2

1. 背景：提升会员活跃度。
2. 功能列表
  2.1 积分商城：展示可兑换商品，按所需积分从低到高排序。
  2.2 兑换：用户选择商品后兑换，积分不足时给出提示。兑换成功后不可取消。
  2.3 兑换记录：展示用户的兑换记录。
3. 页面说明
  3.1 商城页：商品卡片显示图片、名称、所需积分、库存。库存为 0 时显示“已兑完”。
  3.2 确认弹窗：显示商品、所需积分、收货地址，点击“确认兑换”完成兑换。
  3.3 兑换记录页：列表显示商品、积分、时间、状态，可点击“取消兑换”。
4. 规则
  - 每人每天兑换次数有限制。
  - 实物商品需填写收货地址，虚拟商品自动发放。
  - 兑换后积分实时扣减，系统要快速响应。
5. 验收：功能正常，体验良好。
```

## 检查报告

## PRD 检查报告：会员积分兑换 PRD v1.2

结论：修改后进入开发
依据：致命 0 / 严重 4 / 一般 4 / 建议 1；影响测试的问题 7 个

| 编号 | 维度 | 位置 | 问题 | 严重程度 | 影响测试 | 建议改法 |
| --- | --- | --- | --- | --- | --- | --- |
| C-01 | 一致性 | 2.2 兑换、3.3 兑换记录页 | 2.2 写“兑换成功后不可取消”，3.3 有“取消兑换” | 严重 | 是 | 确认是否支持取消，删掉另一处；支持时补充可取消的状态和积分退回规则 |
| C-02 | 确定性 | 4 规则 | “每人每天兑换次数有限制”没有次数和超限提示 | 严重 | 是 | 写明次数和提示，建议“每天 3 次，超出提示‘今日兑换次数已用完’” |
| C-03 | 完整性 | 3.2 确认弹窗、4 规则 | 实物商品没有收货地址时怎么处理没写；虚拟商品发放到哪里没写 | 严重 | 是 | 建议没有地址时“确认兑换”置灰并显示“添加收货地址”入口；写明虚拟商品发放位置 |
| C-04 | 可测试性 | 5 验收 | “功能正常，体验良好”无法判断通过与否 | 严重 | 是 | 每个功能写能观察到的结果，建议“兑换成功后积分减少对应数值，兑换记录新增一条‘待发货’” |
| C-05 | 确定性 | 2.2 兑换 | “积分不足时给出提示”没有提示文案和位置 | 一般 | 是 | 建议在确认弹窗中“确认兑换”置灰，显示“积分不足，还差 N 分” |
| C-06 | 完整性 | 3.3 兑换记录页 | “状态”没有取值，也没写何时变化 | 一般 | 是 | 列出状态和变化条件，建议实物“待发货 → 已发货 → 已完成”，虚拟“已发放” |
| C-07 | 完整性 | 3.1 商城页、3.2 确认弹窗 | 多人同时兑换最后一件库存时的结果没写 | 一般 | 是 | 建议后提交的人提示“已兑完”，不扣积分 |
| C-08 | 确定性 | 4 规则 | “系统要快速响应”没有指标 | 一般 | 否 | 写明指标，建议“兑换结果 2 秒内返回”，或删除 |
| C-09 | 完整性 | 1 背景 | 只写了“提升会员活跃度”，没有目标值 | 建议 | 否 | 补充目标指标和达成时间，便于上线后评估 |

需要我按检查结果出修订版吗？也可以只改指定的问题，例如“改 C-01 到 C-05”。

## 之后可以做什么

- 用户说“根据这份 PRD 出测试用例”时，先就 C-01 至 C-07 提问并附建议答案，确认后再生成用例、YAML 和测试方案；仍不能确认的列为未覆盖。
- 用户说“出修订版”时，先问保持原格式还是改写成本模版，再按 `prd-review.md` 第 4 步修订。
