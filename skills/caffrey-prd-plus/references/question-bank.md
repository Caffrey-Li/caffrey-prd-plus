# 追问题库

用法：草稿写完后，找出标了 TBD 或【待确认】的地方，从下面挑对应问题。规则：

- 一次最多 8 个，按对 PRD 影响从大到小排序：目标与范围 > 协作与影响 > 流程与规则 > 细节。
- 每个问题注明影响章节，并尽量给出选项或建议答案。
- 草稿里已能回答的不问；类型模块和行业包里的「优先追问」优先于本题库。

输出格式：

```
## 待你确认的问题

1. 【三、目标】这次的核心指标是什么？建议：XX 转化率，从 TBD 提升到 TBD。
2. 【六、协作】需要哪些部门配合？我推断有研发、测试、运营，还有吗？
```

## 一、背景与问题
- 这个需求是谁提出的？最初的触发事件是什么？
- 有哪些数据或用户反馈能证明这个问题存在？问题有多严重？
- 为什么要现在做？晚做会有什么损失？

## 二、用户与场景
- 主要给谁用？有没有次要用户？
- 用户现在是怎么解决这个问题的？最痛的是哪一步？
- 最常见的使用场景是什么？

## 三、目标与成功标准
- 做完后看哪个指标判断成功？现在是多少？目标是多少？
- 有没有不能变差的指标（护栏指标）？
- 多久之后评估效果？不达标怎么办？
- 这次明确不追求什么？

## 四、方案概述
- 有没有考虑过其他方案？为什么选这个？
- 方案依赖哪些现有系统？

## 五、范围与版本规划
- 第一版必须包含的最小功能是什么？
- 哪些想法可以放到后续版本？
- 有没有确定的上线日期？是硬性的吗？

## 六、协作与影响范围
- 需要哪些部门和人配合？各自负责什么？谁拍板？
- 会影响哪些现有系统、产品线或功能？
- 会不会改动数据库表、数据口径或历史数据？
- 需不需要研发评估架构调整？
- 有没有外部依赖（第三方、供应商、客户、监管审批）？

## 七、全局与交互规范
- 团队有没有现成的设计规范或组件库？链接是什么？
- 时间、金额、数字的显示有没有统一要求？
- 本需求有没有和通用交互不一样的地方？

## 八、需求详情
- 涉及哪些页面或功能点？哪些是 P0？
- 有没有现成的原型、设计稿或截图？发给我的话，线框图会按它的布局画。
- 有哪些角色？权限有什么区别？
- 对象有哪些状态？状态之间怎么流转？
- 有没有复杂的计算或判定规则？能给个例子吗？
- 出错、为空、超限时怎么处理？
- 这些字段哪些必填？长度和格式有没有现成规范（如姓名、手机号沿用已有系统）？
- 下拉、单选的选项有哪些？由谁维护？默认选哪个？
- 进入这个页面需要满足什么条件（登录、实名、权限、状态）？

## 十、非功能需求
- 预计的用户量、数据量、并发量是多少？
- 有没有性能、安全、合规方面的硬性要求？
- 需要支持哪些设备、系统、浏览器？

## 十一、数据与埋点
- 指标的统计口径是什么？和现有报表一致吗？
- 需要新增哪些埋点？由谁提供数据看板？

## 十二、验收标准
- 测试需要特别关注哪些场景？
- 哪些关联功能需要回归测试？

## 十三、上线与运营计划
- 全量上线还是灰度？灰度按什么维度？
- 出问题怎么回滚？
- 运营、客服需要提前准备什么？

## 十四、风险
- 你最担心这个需求哪里出问题？
- 有没有还没确定、但会影响方案的事？

## 产品总纲（新产品模式）
- 这个产品主要给谁用？团队规模、行业、使用频率大概是什么样？
- 和你参考的产品（如“类似 XX”）相比，最想做得不一样的是哪一点？
- 第一版最少要有哪几个模块才能让用户用起来？
- 部署方式是 SaaS、私有化，还是都要？
- 收费吗？怎么收？
- 团队有多少人？计划多久上线第一版？
- 有没有必须对接的现有系统（账号、IM、代码仓库等）？
