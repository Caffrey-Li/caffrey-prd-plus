# 类型：技术改造 / 重构

**识别信号**：系统重构、架构升级、性能优化、技术债清理、迁移

## 检查项

能写进对应章节的写进去，写不进去的列在第九章（精简版、核心版列在第十四章）。用户没提到、又影响开发的项加入问题清单；无关的项不写。

| 检查项 | 要写清楚的内容 |
| --- | --- |
| 改造原因 | 现状问题与数据（性能、故障、成本、维护难度） |
| 现状与目标架构 | 用缩进列表对比改造前后 |
| 兼容与迁移 | 新旧并行、切流方式、数据迁移 |
| 无感知要求 | 哪些地方用户必须无感知 |
| 回归范围 | 需要回归测试的功能 |

## 对其他章节的要求

- 六、6.4 必写
- 十三、写切流与回滚

## 优先追问

- 改造后用户是否有感知？
- 新旧系统如何切换？

## 通常不适用

- 二、用户与场景；8.3 用户路径；8.4 页面说明
