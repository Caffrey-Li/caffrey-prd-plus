# 生成测试用例

## 前置条件（必须检查）

1. 用户必须提供 PRD 全文。
2. 检查信息卡的「文档状态」和「当前版本」：只有状态为“已定稿 / 开发中 / 已上线”且版本 ≥ v1.0 才生成。
3. 不满足时，回复：“这份 PRD 还是草稿（v0.x），测试用例需要在定稿后生成，避免返工。要我先帮你检查还有哪些内容没定吗？” 然后停止。
4. 用户坚持要生成时，可以生成，但在开头标注“基于未定稿 PRD，仅供参考”。

## 生成规则

- 以第十二章验收标准为主线，结合 8.2 流程、8.4 页面说明、8.5 状态流转、8.6 权限、8.7 规则、第七章规范、第十章非功能需求。
- 每个功能编号至少覆盖：正常、异常、边界三类；有状态流转的覆盖每条流转；有权限差异的覆盖每个角色。
- 第十二章“关联业务回归范围”中的每一项生成回归用例。
- 行业包和类型模块中的硬性要求（如防沉迷、退款、危机转介）必须有专门用例。
- PRD 中仍为 TBD 的地方，不臆造预期结果，单独列在“无法生成用例的待定项”。

## 输出格式

表格可直接粘贴到飞书表格。

```
## 测试用例（基于 PRD v1.0）

| 用例编号 | 关联功能 | 场景 | 前置条件 | 操作步骤 | 预期结果 | 类型 | 优先级 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| TC-001 | F-01 | 正常查看今日预约 | 店长已登录，今日有 3 条预约 | 1. 打开预约页 | 显示 3 条预约，按时间升序 | 正常 | P0 |
```

类型取值：正常 / 异常 / 边界 / 权限 / 回归 / 非功能。

最后输出：
- 用例统计：按功能编号和类型统计数量
- 无法生成用例的待定项
