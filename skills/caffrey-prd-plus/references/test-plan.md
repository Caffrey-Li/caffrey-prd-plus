# 网页 Agent 测试方案

用户确认生成测试用例时，与用例表格、可执行 YAML 一起生成 `【需求名称】-Agent测试方案-v1.0.md`。方案是执行交接，不替代逐条用例；以确认过的 PRD 为预期依据，实际页面只用于定位和记录观察结果，不根据开发实现改写预期。先覆盖网页；其他端不套用网页操作假装已覆盖。

## 方案内容

1. **依据与范围**：PRD 名称、版本，用例表和 YAML 文件名，目标功能编号、覆盖范围与不在范围内的内容；按功能或验收编号映射用例编号，列出无法生成用例的原因，不编造行为。依据是其他格式的已有 PRD 时，附功能编号与原文章节的对照表，以及生成前用户确认的答案。
2. **执行条件**：被测网址、环境类型、测试账号和数据的变量名及准备责任人，浏览器和所需电脑操作能力；不写真实凭据。实际地址、环境和数据由用户在执行前提供或确认。
3. **执行顺序与操作**：先读 PRD、方案和 YAML；检查环境、数据和操作工具，向用户汇总并取得开始确认；用浏览器或电脑操作工具从入口进入，按 YAML 的 setup、steps、expect、cleanup 逐条操作并截图。按可见文字、角色及页面上下文定位，不依赖源码、接口或预先知道的选择器；有多个候选或页面与用例不一致时记录并判断，不能确认时阻塞或列为疑似用例问题，不猜测或更改预期。
4. **安全与中断**：生产环境只跑 `prod_safe: true`；真实交易、通知或修改真实数据等危险步骤按执行技能规则停下确认。无法访问、登录失败、验证码、缺工具或测试数据时记录阻塞；遇到需要人工处理的步骤记录需人工。不得绕过验证或使用真实个人信息。
5. **结果与交付**：先给出上线结论：建议上线、有条件上线、不建议上线或无法判定，判定规则见 `caffrey-test-runner/references/results.md` 第二节；再逐条记录通过、失败、阻塞、需人工或跳过及实际结果、截图证据；汇总数量、范围、未覆盖项和原因、失败缺陷草稿及疑似需更新的用例。没有执行的不能写通过。能写文件时按 `caffrey-test-runner/references/results.md` 输出结果表、机器可读结果、截图和缺陷单；不能写文件时在对话中给出结果和可用证据。

## 给执行 Agent 的交接话术

“请读取这份测试方案、对应 PRD 和 YAML 用例，在我确认被测地址、环境、数据及执行范围后，使用可操作的浏览器逐条测试，保留截图，先给出上线结论，再输出结果表、统计、缺陷草稿和未覆盖原因。不要依据实际实现修改预期。”
