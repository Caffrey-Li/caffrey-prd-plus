# 全包交付

用户在第 1 步选择“全包”时使用。交付一个压缩包：需求文档（Markdown）+ 线框图图片 + 清单 + 导入说明。别的 agent 拿到后，能按原来的层级导入飞书知识库（Wiki），图片放回原位。

只能聊天、不能生成文件的平台不用全包，改为在对话中输出文本版。

## 一、目录结构

```
咨询师列表增加只看今天可约-PRD-v0.1/
  manifest.yaml                 页面清单（Wiki 层级）和图片清单，由脚本生成
  IMPORT.md                     给导入 agent 的说明，由脚本复制
  pages/
    01-咨询师列表增加只看今天可约.md
  images/
    F-01-咨询师列表.svg          线框图源文件
    F-01-咨询师列表.png          由脚本从 SVG 转成
```

- 目录名：`需求名称-PRD-版本号`，去掉引号、斜杠、冒号等特殊字符。
- 一个 Wiki 页面一个 md 文件，文件名以两位序号开头，决定页面顺序。
- 子页面放在与父页面同名的子目录中。新产品模式示例：

```
pages/
  01-产品总纲.md
  01-产品总纲/
    01-M01-账号与组织.md
    02-M02-工作项.md
```

## 二、页面写法

1. 正文与文本版 PRD 相同，只有线框图不同：8.4 中写 `![F-01 咨询师列表 线框图](../images/F-01-咨询师列表.png)`，不再放文本线框图。图片画法见 `wireframe.md` 第六节。
2. 用户路径图（完整版 8.3）仍用 `text` 代码块，飞书中会显示为代码块。
3. 「自检结果」「待你确认的问题」**不写进页面**，放在对话回复里。
4. 只用标准 Markdown：标题、表格、列表、加粗、引用、代码块、图片。不用 HTML 标签。

## 三、生成步骤

1. 建目录，写 `pages/` 下的 md 文件。
2. 每张线框图画成 SVG，放进 `images/`。
3. 运行打包脚本（在本技能目录的 `scripts/` 下）：

```
python3 scripts/make_bundle.py 咨询师列表增加只看今天可约-PRD-v0.1
```

脚本会：把 SVG 转成 PNG（依次尝试 cairosvg、rsvg-convert、Playwright）；检查正文引用的图片是否都存在；生成 `manifest.yaml`；复制 `IMPORT.md`；打成同名 zip。

4. 脚本报错时按提示处理。无法运行 Python 或无法转 PNG 时，仍然交付目录，在回复中说明“图片为 SVG，导入飞书前需转成 PNG”。

## 四、交付时的回复

压缩包作为文件发给用户，回复中只写：

- 一句话：包里有什么（几个页面、几张线框图）。
- 「自检结果」1-3 行、「待你确认的问题」。
- 导入方法：把压缩包交给能操作飞书的 agent，说“按 IMPORT.md 导入飞书 Wiki”；或按 IMPORT.md 末尾的手动方法导入。

不要在回复里再贴一遍 PRD 全文。

## 五、迭代与后续内容

- 每次修改后生成新的完整全包，目录名中的版本号随之更新（v0.2、v0.3……）。
- 定稿后用户要求的测试用例：加一个页面 `pages/02-测试用例.md`（飞书表格），可执行 YAML 放在 `attachments/` 下；原型图 HTML 也放在 `attachments/`。重新运行脚本打包。
