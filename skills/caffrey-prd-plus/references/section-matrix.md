# 规模分级与章节取舍

## 一、判断规模

| 规模 | 判断参考（满足任一条即可升一档） |
| --- | --- |
| 小 | 单一模块、不跨部门、无数据结构变更。例：改字段、调文案、加一个筛选、修改一条规则参数 |
| 中 | 涉及 2-3 个模块或 1-2 个协作部门；有新页面或新流程；有少量数据结构变更 |
| 大 | 新产品或新业务线；跨多个系统或部门；有架构调整或数据迁移；B 端交付项目；硬件项目 |

拿不准时取较大的一档，并在第 1 步确认时说明理由。

## 三、条件章节的判断规则

| 章节 | 写 | 写【不适用】 |
| --- | --- | --- |
| 二、用户与场景 | 有用户或客户直接感知的变化 | 纯技术改造、纯数据底层建设 |
| 七、全局与交互规范 | 有界面 | 无界面时 7.1 照写，7.2 写不适用 |
| 8.2 业务流程 | 有多步骤或多角色流程 | 单点改动 |
| 8.3 用户路径 | 新增或改动页面跳转 | 无界面或不改跳转 |
| 8.4 页面说明 | 有界面 | 无界面（API、策略、数据底层） |
| 8.5 状态流转 | 对象有 3 个及以上状态 | 无状态或状态不变 |
| 8.6 角色与权限 | 多角色或有权限差异 | 单一角色且无权限变化 |
| 8.7 业务规则 | 有计算、判定、匹配、排序逻辑 | 无 |
| 8.8 接口对接 | 跨系统交互 | 单系统内 |
| 十、非功能需求 | 有性能、安全、合规、兼容要求或行业包要求 | 纯文案或配置调整 |
| 十一、数据与埋点 | 有量化目标或新增数据 | 三章写明无量化目标时 |
| 十三、上线与运营计划 | 用户可感知、需灰度、需运营或客服配合、有数据迁移 | 内部微调 |

## 四、类型对章节的影响

各类型文件末尾的「通常不适用」会把对应章节或子项改为【不适用】。多个类型冲突时，**只要有一个类型需要，就保留**。
