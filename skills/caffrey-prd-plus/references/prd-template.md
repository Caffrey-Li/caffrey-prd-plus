# PRD 核心模版

本文件是 PRD 的固定骨架。`> 写法：` 引用块是写给你（AI）的说明，输出时删除。表头不变，行数按内容增减。写哪些章节以用户在第 1 步选的版本和板块为准（`section-matrix.md`）。

## 写作要求（逐句检查）

1. **一句话说清**：能一句话说清的只写一句；表格单元格写短语，不写完整句子。
2. **不补充**：不写“说明：”“注：”“补充：”“也就是说”“即”“需要注意的是”这类补充语；不解释显而易见的原因；不写“提升体验”“方便用户”这类空话。
3. **一处一说**：每类内容只写在下表的归属位置；其他地方需要时写编号引用（如“见 F-03 ②”“见 Q-01”），不复述内容。
4. **没有就不写**：没有内容的行、列、小节直接删除，不写“无”“暂无”“同上”。

| 内容 | 唯一归属 | 其他地方的写法 |
| --- | --- | --- |
| 为什么做 | 一 | — |
| 目标指标 | 三 | 11.1 只写口径 |
| 功能清单（本期做什么） | 8.1 | 五只写“本期不做”和后续版本 |
| 业务流程与分支 | 8.2 | 四只写一句话方案；8.3 只写页面跳转 |
| 页面行为规则 | 8.4「操作与规则」 | 十二写“满足 F-01 ①–③” |
| 字段格式、校验、提示文案 | 8.4「字段与组件」或 8.9 | 操作与规则中不再写校验 |
| 跨页面的计算、判定规则 | 8.7 | 8.4 写“见 R-01” |
| 状态及流转 | 8.5 | 8.9 不再列状态枚举，写“见 8.5” |
| 通用规则、通用交互 | 7.1、7.2 | 8.4 只写例外，遵循的不写 |
| 待确认的问题 | 6.6（精简版、核心版在十四） | 正文写【TBD：见 Q-01】 |
| 行业合规项 | 所在章节，行末加【合规】 | 不再汇总 |
| 变更内容 | 附录 C | 信息卡不再写变更摘要 |
